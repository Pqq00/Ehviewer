feat(cache): cap parsed-model cache and decouple bitmap budget

The parsed-model database grew without a limit: TTL pruning only removed
expired rows, so a heavy user kept everything fetched within 7 days. It
now has a 24MB content quota and evicts the least recently fetched list
pages and details until it fits. The quota is measured on row payload
bytes because SQLite does not shrink its file after deletes.

The HTTP layer also stops storing single responses above 4MB, which are
not page markup and would otherwise crowd out normal entries.

Bitmap cache used to share pageCacheLimitMb with the on-disk image cache,
so 500MB of disk imagery also meant 500MB of decoded bitmaps. It now has
its own bitmapCacheMb budget (32-512MB, default 128) exposed in reader
settings, and the reader LRU follows it.
